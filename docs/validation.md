原始快速档揭示两处最终答案解析过窄：带中文结论的正确答案没有被识别。修正后使用同一批保存的回答生成 `validation-quick-regraded`，两处重新判为正确，保留 `original_grade`。指纹运行的一条 Claude 拒答原先被 CLI 的 `success` 子类型遮蔽，修正后生成 `validation-fingerprint-regraded`，状态正确记录为 `refused`，有效回答数与匹配结果不变。这两份派生记录没有新模型调用，不是第二轮独立实验，也不用于展示模型性能提升。

指纹输出仅用于检查闭集报告链路：Codex 对应最高候选 `gpt-6-astra`，Claude 两份有效回答对应最高候选 `claude-sonnet-5`。后者 CLI 实际返回的模型字段为 `claude-fable-5`，不在当前候选库中；这一现象正说明候选匹配不能当作身份认证。字段自报、库内概率与真实身份是不同证据。

脱敏结果摘要见 [validation-observations.json](../examples/validation-observations.json)。它保留运行 ID、状态和原始/派生标记，不含凭据、私有地址、原始回答或本机用户路径。本机原始证据位于忽略的 `runs/` 下，包括请求、回答、用量、事件和报告；不推送远程。临时接入配置位于 `runs/validation-config.yaml`，不影响仓库默认配置。

## 尚未验证的范围

- 未进行真实的 full 189 题调用或多轮统计研究；不能据此报告全题库能力分数或回归显著性。
- API 两种协议有离线验证，没有成功的真实接入证据。配置匹配的地址和凭据后需重新运行 quick 与 fingerprint。
- 人工评阅界面和导入导出已验证，真实开放题尚未由评阅者评分。
- native 模式保留本地配置与工具，因此环境依赖和工具能力会影响结果；不能和 controlled 混合比较。
- CLI 能力取决于本地版本及管理员配置。受控模式关闭支持的可配置功能并检查实际工具事件，但不能抹去供应商内置指令；不支持必要控制选项的版本会报错。
- 原始运行早于最终提交。离线重判明确保留来源，不伪装为最终提交上的重新采样。
