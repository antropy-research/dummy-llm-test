# 方法与证据边界

## 评测对象

本项目检测可观察的答题表现、格式遵循、工具使用与输出指纹。quick 是筛查，full 是题库覆盖；两者都不是通用智力测试，也不能据此证明服务商更换了底层模型。

API 每道题独立请求，不传会话历史或工具。受控 CLI 每道题建立新的临时工作目录及临时会话，关闭可配置的记忆、搜索、工具和扩展，审计返回事件。Codex 的 read-only 本身不能禁止读文件和计算，因此还显式关闭 shell、unified_exec、apps、plugins、multi_agent 等开关；Claude 使用 safe-mode、空 tools 和空 MCP 配置。

CLI 内建和管理员管理的系统提示可能仍存在，不能把它当作 API 裸模型的等价条件。受控模式发现工具事件会标记 protocol_violation。日常模式保留本地工具和配置，记录其使用及主要配置文件哈希；该哈希不覆盖全部动态记忆、外部 MCP 状态或服务端变化，所以日常模式回归仍需结合实际环境解释。两种模式不混排。

每个 CLI 工作目录不包含答案和题库文件。运行器仅传入 prompt/system；评分、答案和参考解释只留在本地证据及人工评阅包中。日常模式有本地工具权限，不是隔离第三方恶意模型的安全沙箱。

## 糖果：先明确题意，再讨论答案

原题的形状可由手感区分。允许事先决定分别取多少圆形和星形时，最小总数为 21，组合为圆形 9、星形 12。若完全随机抓取、不能按形状选择，最小总数是 29。

本项目用独立枚举器遍历所有六种糖果的可能抽取数量。没有圆形苹果×星形桃子或圆形桃子×星形苹果的样本属于失败集合；在可选择的形状数量对中找到最小保证成功组合。这同时给出低于最优值的反例边界，不依赖模型解释或上游评分器。

原题保留两份结果：上游兼容分检测独立的 `21`，严格分解析明确的最终答案。比如“21 是错的。Final Answer: 29”兼容分为 1、严格分为 0。严格解析接受 `Final Answer`、最终独立答案、明确中文数值结论；含歧义或无法解析的客观答复记 unparsed，严格分为 0，并单列状态。9.9 更大这类明确结论不会仅因附带短语而误判。参数变体明确写出按形状选择的规则，不与原题提示词混称。

## 开放题

SVG 只自动检查 XML 和预览安全性，不用几何形状猜测动物正确性。脚本、事件属性、外部引用、危险嵌入、CSS 导入、DTD/实体和超大内容不会进入预览；展示使用图片上下文，不把模型 XML 内联进报告 DOM。

人工 SVG rubric 版本 `svg-v1`：subject、vehicle、riding、overall 各 0/1/2 分。BullshitBench rubric `bullshit-v1`：0 接受错误前提，1 部分质疑但继续接受，2 明确指出问题。保留原始参考解释，允许备注；这不是复现其上游多模型裁判分。

匿名评阅隐藏目标元数据、按不透明样本 ID 排序；模型自己的回答仍可能透露身份。评分必须包含全部维度和评阅者，历史导入不删除，当前报告使用每个样本最近导入的评分。未评分不当作零分，各维度均分仅覆盖已评样本。

## ModelTrace

固定使用提交 `60949ef522a84f66b1236b459308b48028d36949` 的核心评分代码与统一库，保留 MIT 许可。当前快照为两个家族、13 个候选；GPT 参考来源是 Codex，Claude 参考来源为上游标注的 OAIPro。它们是上游参考标签，不是本项目独立认证的身份。

三条检测挑战各要求约 292–332 个 1..355 整数。上游检测生成器与 36 条建库挑战不是同一入口，本项目使用前者；固定 seed 是本地可复现扩展，生成措辞沿用上游。每组按清单顺序采集，每次重复单独计算，不能把任意数量回答混成一组再错误套用三份校准参数。

上游解析器选最长连续数字段、过滤到 1..355；每份门槛为 `max(80, ceil(expected_count × 0.55))`。通过这个门槛不等于严格满足要求的数字个数，也不证明数字真正随机。保留实际解析数量、门槛和有效标记。已知截断、拒答、失败或使用工具的响应不进入匹配；默认不补采直到成功。

提取数字分布和有序块特征，去除上游拟合的部分环境干扰方向，按库内权重融合，再用对应有效回答数的校准温度转为概率。家族概率由候选概率求和。候选库外模型仍会匹配已有候选，因此高概率不能证明真实身份；不同采集渠道、提示条件及库版本也会影响结果。

自动测试验证包装层与固定上游代码对相同输入的解析、分数、排名和概率一致。这是实现一致性，不是外部识别准确率验证。

## 回归与统计

只匹配相同目标名、case 哈希、实验目标签名、模式、评分器签名以及实际响应模型字段的样本。0.4.0 新签名将接入协议与调度/报告分开：并发和价格不进入能力签名，性能比较仍检查运行条件；旧签名不自动迁移。具体字段见[兼容规则](compatibility.md)。缺少基线、参数改变、题目改变分别可见；不兼容样本不产生回归差值。目标相同不证明后台权重相同，反之目标不同的对照也不作回归判定。

分类报告显示严格正确率、每题重复结果和首轮 Wilson 95% 区间。历史比较按题目聚类，对每题的重复差值求平均，再用固定 seed 的 2,000 次配对 bootstrap 给出差值区间。少于 30 个不同题标为 screening_only；单题不给 bootstrap 区间。全对/全错或极小样本可能出现退化区间，不能理解成没有不确定性。

故障率、待评阅、知识日期自述、人工评分和指纹单独报告；不把错误请求排除后的一小批成功样本包装成全量通过。无因果对照时不归因于模型被替换、IP、账号、推理预算或训练污染。

## 运行产物

| 文件 | 内容 |
|---|---|
| `manifest.json` | 配置、题目/提示词快照、版本/哈希、目标信息、运行计划、预算 |
| `attempts.jsonl` | 每次尝试的开始与完成事件，包含请求和响应 |
| `results.jsonl` | 每个完成样本的回答、用量、状态、工具、评分和尝试记录 |
| `summary.json` / `report.html` | 分类、人工评阅、指纹及运行故障汇总 |
| `challenges.json` / `fingerprint_bank.json` | 此次 ModelTrace 的挑战与指纹库快照 |
| `reviews.json` | 追加保存的人工评阅历史 |

新运行逐条追加完成结果；进程中断可续跑。保留配置凭据变量名，但不保存凭据值；已知环境密钥会从响应和错误中脱敏。原始运行目录仍包含本地路径、回答和模型信息，默认被 Git 忽略。
