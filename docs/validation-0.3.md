# 0.3.0 性能观测验证

日期：2026-09-15。验证范围为尝试/样本耗时、SSE 观测、执行片段、性能汇总及历史
比较。全部使用固定数据、可控时钟、内存 HTTP 模拟流和本地模拟 CLI；**没有付费
模型调用，也未读取、重判或覆盖用户的原始运行记录**。

## 验证结果

- Python 3.11 与 3.12：各 **134 项离线测试通过**，Ruff 及仓库契约检查通过。
- 可控单调时钟验证两次尝试 2s / 3s，中间等待 1s：样本总耗时 6s，30 个输出 token
  的最终尝试 TPS=10、样本有效 TPS=5。UTC 时钟调整不影响时长计算。
- 验证重试等待被中断时，已等待部分仍计入总耗时；失败、空回答和缺失用量不会
  被计入成功性能统计或伪装为零。原有超时、CLI 中断、续跑及 189 题模拟调度测试保留。
- 两种 API 协议的本地 SSE 模拟流验证：角色、心跳、工具、推理和最终完整回答不
  冒充正文增量；终态停止读取、截断和拒答分别记录，超时前的正文与到达事件保留。
  非 SSE 响应报错且不切换协议。用事件屏障确认正文在终态前已被实际消费。
- 推理 token 保留服务端值，所有纯生成速率保持空值及原因；离线可从已有事件
  重新计算可见文本边界，但不能从最终完整回答推测首段时间。
- 可控重叠区间验证时长 4s、峰值并发 2、平均并发 1.5；用量只有一半时完整吞吐
  留空，已知部分 30/4=7.5 token/s、覆盖率 50%。第二次启动单独计时，不包含离线间隔。
- 真实本地线程的屏障测试验证重叠尝试数；续跑新增片段，原片段保持不变。空续跑
  没有时长及速率；异常退出留下未闭合区间时不报告完整时长。
- 历史比较验证并发、重试、超时、stream、输出上限不同均标为条件不同；当前缺失
  的基线样本明确列出。配对变化同时包含长度与故障率，基线零值不计算百分比。
- 旧记录性能分析生成新目录并校验原文件字节不变。缺失样本跨度、排队和首段时间
  保持为空；HTML 特殊字符转义、缺失值及已知零值的区分均有测试。
- 使用本机 Chromium 实际渲染合成数据的耗时直方图、输出 token—耗时散点图和
  并发曲线，检查了覆盖率与缺失吞吐的显示。此截图只验证 UI，不是真实模型数据。

## 复核命令

```bash
uv sync --frozen
uv run python scripts/check_repo.py
uv build
uv run python scripts/make_performance_example.py --output runs/performance-example
```

最后一条只生成明确标为合成数据的 `performance.json`、`report.html` 与
`comparison.html`，不进行任何模型请求；输出目录必须不存在。

## 实测与兼容性边界

真实 OpenAI 及兼容服务商的流式 HTTP 接入尚未实测；本地模拟流测试不能替代该证据。
CLI 当前没有增量正文到达时间采集，因此不提供首段时间，显式 `stream:true` 会报错。
用量是供应商报告的总输出 token，可能包含推理；不能据此宣称纯生成 TPS。

旧报告仍可读取并离线派生分析。原有源码/配置哈希检查保留，因此本轮不支持跨版本
续跑或直接宣称旧版与新版性能可比。按目标的性能、人工评分、能力分数及指纹结果
保持独立，不对单次性能变化作降智判断。字段、公式、支持矩阵见[性能说明](performance.md)。
