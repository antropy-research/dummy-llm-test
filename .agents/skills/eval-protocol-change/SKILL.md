# 评测协议变更

先读取仓库根目录的 AGENTS.md；按任务查阅 docs/research.md、docs/methodology.md
和 THIRD_PARTY_NOTICES.md，不把历史验证报告视为当前接入状态。

新增题目先说明原题复现还是本地扩展。复现使用固定上游版本、逐字提示词、
数据校验值与适用许可；扩展分配独立题号与来源。未声明许可的代码不整包复制。
修改来源脚本时只执行任务需要的下载，不顺带更新所有第三方快照。

判分修改先建立有明确预期的通过、失败和边界样本。数学变体的答案用独立方法
核验；严格最终答案不能退化成“正文包含答案”。Candy 原题宽松兼容分单独统计。
ModelTrace 修改用同输入、同库与固定上游比较解析、有效门槛、排名和概率，
包括 0–3 份有效回答、工具生成的无效归因与不兼容库。

检查发送给目标的实际消息中没有 expected、rubric、参考答案或开发指令。
开放题仍人工评阅，自报日期不进入能力准确率；解析成功不是答案正确的证据。

变更题号、提示词、评分器或比较字段时，说明哪些旧记录仍可比较。不要为显示
回归结果而跳过兼容检查；要迁移时保存来源与新版本。评分器修正只离线 regrade
已有回答，保留原记录；它不能充当一次新的模型实验。

按变更运行 tests/test_catalog_scoring.py、tests/test_fingerprint.py 或
tests/test_runner_review.py 的相关测试，更新用户可见协议文档。最终说明来源事实、
本地扩展、验证结果和不能由这些证据得出的结论。
