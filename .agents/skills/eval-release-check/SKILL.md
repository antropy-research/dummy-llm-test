# 发布与证据检查

从当前 Git 状态、实际变更及用户本次授权开始。发布检查不自动授权推送、
创建 Release、上传 PyPI 或修改仓库可见性；已有授权不必重复询问。

运行 `uv run python scripts/check_repo.py`。涉及打包或正式版本发布时再执行
`uv build`，检查源码包与 wheel 含必要题库、许可和来源，且不含 runs、私有配置、
密钥或缓存。在仓库外验证安装后能读取题库；仓库内 editable 成功不等于打包成功。
CI 不得因导入模块或新增测试隐式调用付费模型。

检查 README、配置说明、变更记录、包版本及锁文件是否描述最终行为。
评测声明必须标明源码版本、离线/真实、完整/部分、原始/重判；不要覆盖历史验证
记录以制造“当前版本全部实测成功”。公开示例应去掉原始私有回答和接入地址。
检查待提交文件及包内容中的凭据，但不把凭据值打印到日志。

核对第三方固定版本、校验值、保留许可和未声明许可的例外。不要把第三方全部
归为本项目 MIT。尚未解决的分发安排应明确记录，不宣称已获授权。

若推送已授权，先核对远程新增提交并整合，禁止强制覆盖；推送后核验本地提交
和远程目标分支一致。最终只报告确实完成的检查与发布动作，说明阻塞点及其来源。
