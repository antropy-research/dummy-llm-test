# 测试题:Collatz 猜想(徒手版)

> 不用装任何东西。打开你常用的大模型聊天网页(ChatGPT / Claude / Gemini / 豆包 / 千问 / Kimi / DeepSeek……都行),按下面三步走,五分钟搞定。

---

## 第一步:把下面这一整段粘进对话框,发送

```
从整数 1 到 1000 中随机选一个数 n。操作规则：如果 n 是偶数，我可以把它变成 n/2；如果是奇数，我必须把它变成 3n+1。我不断重复这个过程，直到第一次到达 1 为止（假设总会到达 1）。
问题：在 1 到 1000 中，有多少个数在这个过程中，第一次进入 1 之前，会至少出现一次数值是 16？
我的思路：既然假设总会到达1，那就从1反推，2（来源不合法），4（来源还是1），8（来源不合法），16，也就是所有入口都是16，也就是除了这几个数之外，都会经过16。
禁止写代码，禁止运行脚本，禁止深度思考，凭直觉给出你的看法。
```

---

## 第二步:对照答案

**正解:996。**

一句话推理:到 1 之前必经 `16 → 8 → 4 → 2 → 1` 这条尾巴(逐级反推每个节点的入口都唯一,直到 16 才分叉)。所以 16 是必经瓶颈,只有它下游的 `{1, 2, 4, 8}` 这 4 个数绕得开。`1000 − 4 = 996`。

**模型常见的几种翻车:**

| 它给的数字 | 它在干嘛 |
|---|---|
| 920 / 222 / 570 / 23 / 358 / 618 ……(每次不一样) | **张口编个数**,前面常带"对 1 到 1000 逐一计算可得"——它没算,问它"你怎么算的"通常说不清 |
| 336 / 39 / 31 / 23 | 走了"反推 16 祖先树"路线、数错了——这题考的不是树,是瓶颈 |
| 668(还会附"二进制不含连续 4 个 0"理论) | 自创理论,推得很优美,核心是错的 |
| 14 | 把全集硬缩成两条倍增链,典型审题失败 |
| 995 | **不算错,是定义之争**——它认为"起点 16 不算路过 16",于是排除 `{1,2,4,8,16}` 5 个数 |
| 996 ✅ | 抓到瓶颈,这就是正解 |

如果模型一开始还试图"挑你的错"、说你漏了什么分支,但最后仍给出 996——这是好兆头。如果它"挑错"完给了 920 之类,那它是在**为反对而反对**(典型的过度自信)。

---

## 第三步(可选,**最关键的对照**):换个推理模式再问一遍

如果你用的聊天工具有 **"深度思考 / Reasoning / Extended thinking"** 之类的开关:

- **关掉它,重新问一遍同样的话。**
- 看答案有没有变。

**我们的发现**:很多模型**开了思考就答对、关了思考才露馅**。GPT-5.5 关推理给出 920,开推理立马变 996。这道题真正测的是**敢不敢忍住不算**。
